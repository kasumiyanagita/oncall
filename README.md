# oncall

障害対応をこなしながら Linux コマンドを身につけるターミナルゲームです。
プレイヤーは新人 SRE。深夜にページャーが鳴り、壊れたサーバーに入って本物のコマンドで原因を突き止めます。

Ubuntu(Windows の WSL2 上の Ubuntu を含む)で動きます。

## 初回のセットアップ

このディレクトリで、最初に 1 回だけ実行します。

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
ln -sf "$PWD/.venv/bin/oncall" ~/.local/bin/oncall
```

最後の行は、どのディレクトリからでも `oncall` で起動できるようにするためのものです。

## 起動

```bash
oncall
```

どのディレクトリで実行しても構いません。作業用のファイルは `/tmp/oncall-xxxx/` に作られ、ミッションを離れると消えます。
`oncall` だけなら、いまの端末で、通常のデザインのまま起動します。

### レトロなデザインで使う(Windows Terminal)

最初に 1 回だけ、準備をします。Windows Terminal に「oncall」というプロファイルが 1 つ増えます(ほかのプロファイルは変わりません)。

```bash
oncall --retro-install
```

それ以降は、次のコマンドで、レトロなデザインの新しいタブが開いて起動します。

```bash
oncall --retro
```

レトロのデザインは、通常のデザインとは別に作ってあります。緑一色のブラウン管の端末を手本にしていて、
色は緑の濃淡だけ、記号と枠は `*` `#` `+--+` のような文字だけを使い、ロゴも別のものです。
やめるときは `oncall --retro-remove` を実行します。

| デザイン | ファイル |
|---|---|
| 通常 | `src/oncall/designs/normal.py` |
| レトロ | `src/oncall/designs/retro.py`(フォントなど端末の設定もここ。変えたあとは `oncall --retro-install` で反映) |

2 つのファイルは互いに何も共有していません。片方を変えても、もう片方は変わりません。

## 遊び方

初めて起動したときは、最初にチュートリアル(4 ページ)が出ます。2 回目からは出ません。
もう一度見たいときは、トップページで `tutorial` と打ちます。

どの場面でも、`title` はトップページに戻る、`exit` はゲームを終了する、という意味です。

### トップページ

```
╭─ インシデント一覧 ─────────────────────────────────────────────────────────────╮
│ No     インシデント                難度   主なコマンド              結果        │
│  1  ✓  深夜の 500 祭り             ★★☆☆☆  grep awk sort uniq head   A 85pt 6:12 │
│  2     満杯のディスクと開いた鍵    ★★☆☆☆  find du chmod             未解決      │
╰────────────────────────────────────────────────────────────────────────────────╯
  解決したインシデント  14%  ━━━━━━━━━━━━━━━━━━━━  1/7
  コマンド図鑑          25%  ━━━━━━━━━━━━━━━━━━━━  5/20

── Enter インシデント 2 │ zukan 図鑑 │ tutorial 使い方 │ exit 終了 ─
> Enter / 番号を入力(例: 1)        ← 何も打っていないあいだ、薄く出る案内
```

| 操作 | 働き |
|---|---|
| Enter | まだ解決していない最初のインシデントを始める |
| 番号を打って Enter | そのインシデントを始める |
| ← → | 前後のページへ移る(1 画面に収まらないときだけ) |
| `zukan` | コマンド図鑑を見る |
| `tutorial` | チュートリアル(進め方の案内)を見る |
| `exit` | 終了する |

### ミッション中

画面は上から 3 つに分かれています。

```
(表示: 依頼の文章、打ったコマンドとその結果がここに流れます)

──── mission 依頼 │ hint ヒント │ check 判定 │ zukan 図鑑 │ title 戻る │ exit 終了 ─
● you@prod-api-01:~/incident $ awk '$9 == 500' access.log     ← 入力欄: ここに打ちます
──────────────────────────────────────────────────────────────────────────────────
 ● INCIDENT 深夜の 500 祭り  目安 7:00 / 12 コマンド           ← いま対応しているインシデント
   mission で依頼をもう一度表示、check で解決したか判定します。
   → ~/incident/answer.txt がまだありません。…                 ← 直前の判定への指摘
```

打ったコマンドは本物の bash で実行されます。次の言葉は、ゲームが受け取って処理します。

| 言葉 | 働き |
|---|---|
| `mission` | 依頼(チケット)をもう一度表示する |
| `hint` | ヒントを 1 段階開く(減点あり) |
| `check` | 解決できたか判定する |
| `zukan [コマンド名]` | コマンド図鑑を見る |
| `title` | トップページに戻る |
| `exit` | ゲームを終了する |

入力欄では、←→ での移動、↑↓ での履歴、Tab での補完が使えます。
`less` や `vim` を開いているあいだは、入力欄に閉じ方(「q で閉じる」など)が出ます。

クリアすると、所要時間・コマンド数・ヒント数・判定ミスからランク(S / A / B / C)が付き、
模範解答と別解の解説が表示されます。そのままシェルで別解を試せます。
ログなどのデータは毎回ランダムに生成されます。

## ミッション

| No | インシデント | 主なコマンド |
|---|---|---|
| 1 | 深夜の 500 祭り: アクセスログから 500 エラーの多い送信元を特定する | grep awk sort uniq head |
| 2 | 満杯のディスクと開いた鍵: 古くて大きいファイルを消し、秘密鍵の権限を直す | find du chmod |
| 3 | 置換ひとつで直るはずだった: 複数の設定ファイルをまとめて修正する | sed diff |
| 4 | 壊れたファイルを隔離せよ: 中身で絞り込んだファイルをまとめて移動する | xargs mv |
| 5 | 止まらないワーカー: 暴走しているプロセスを特定して止める | ps kill tail |
| 6 | 消えた注文: 書式の違う 2 つのログを突き合わせる | cut comm join |
| 7 | 同じ夜を繰り返さない: エラーの急増を検知するシェルスクリプトを書く | wc test |

## 進捗とコマンド図鑑

インシデントを解決すると、自己ベストが保存され、そのミッションで扱ったコマンドが図鑑に登録されます。
図鑑では書式、よく使うオプション、使用例と、自分がそのコマンドを使った回数を確認できます。
トップページでもミッション中でも、`zukan` で開けます。

セーブデータは `~/.local/share/oncall/progress.json` に保存されます
(`XDG_DATA_HOME` や `ONCALL_DATA_DIR` で場所を変えられます)。`oncall --reset-progress` で消せます。

## 実行方式

プレイヤーのコマンドは本物の bash で実行されます。

- **隔離モード**: `unshare` で名前空間を分け、`/usr`・`/etc` と使い捨ての作業用ホームだけが見える環境で動かします。
  本来のホームや `/mnt`(WSL では Windows のドライブ)は存在せず、ネットワークと他のプロセスも見えません。
- **簡易モード**: 名前空間を作れない環境で自動的に選ばれます。使い捨てディレクトリをホームにし、
  その外への `cd` や、外のファイルを書き換えるコマンドを止めます。`kill` は、そのミッションで起動された
  プロセスを数字の PID で指定したときだけ使えます(`pkill` は使えません)。入力ミスによる事故を防ぐためのもので、
  完全な隔離ではありません。

隔離モードを使えない環境では、始める前に「隔離モードで実行できなかったので、簡易モードで実行します。よろしいですか?」と確認が出ます。
`--mode isolated` / `--mode guard` で明示的に選べます。

## ミッションの追加

`src/oncall/missions/<名前>/` に次の 2 ファイルを置くと、ディレクトリ名の順にトップページの一覧へ並びます。

- `mission.toml`: タイトル、チケット文、ヒント、解説などの文章と、図鑑に登録するコマンド名
- `scenario.py`: 作業ディレクトリを作る `generate(home, rng)` と、正誤を判定する `check(home, ctx)`

`generate()` が返した辞書は `check()` に渡され、文章中の `{{名前}}` の置き換えにも使われます。
`scenario.py` には、シェルの中で実行する bash スクリプトを返す関数も置けます。
`shell_setup(ctx)` はシェルの起動時に(プロセスを動かしておくミッション用)、
`precheck(ctx)` は `check` のたびに判定の直前に(プレイヤーの書いたスクリプトを実行するミッション用)実行されます。
正解データはゲーム本体のメモリにだけ置かれ、作業ディレクトリには書き出されません。

図鑑の内容は `src/oncall/commands.toml` にあります。ミッションで新しいコマンドを扱うときは、ここに項目を足します。

## テスト

```bash
.venv/bin/pytest
```

各ミッションについて、模範解答と別解で解決になること、ありがちな雑な解き方では解決にならないことを、
実際のシェル環境(使える環境では隔離モード)で確かめます。あわせて、ゲーム全体を起動して、
トップページからミッションを解いて終了するまでの流れも確かめます。全体で 3 分ほどかかります。
